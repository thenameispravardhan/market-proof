AI NEWS TRADING BOT — IMPROVEMENT PLAN
=======================================
(Consolidated roadmap. Constraint: NEVER destroy the existing setup — every new
behavior ships behind a frontend toggle, defaulting to the current behavior.
All controls live in the UI; no file sentinels or CLI gates.)

PHASE 0 — MEASURE FIRST (1-2 days, run alongside Phase 1)
---------------------------------------------------------
 1. [DONE] Instrument per-stage latency: every analysis now records
    pdf_fetch_ms / pdf_extract_ms / llm_ms / total_ms /
    news_age_s_at_start in analyses.raw_response.timings and logs an
    `analyzer.pipeline_timing` line (track=fast|llm).
 2. [PENDING - OPERATOR] Run a trading day, read the timing logs, and
    confirm where the 30-40s actually goes before optimizing Phase 3.

PHASE 1 — REAL NEWS TEXT INTO THE PIPELINE (fixes wrong signals)
----------------------------------------------------------------
 3. [DONE] PDF prefetch in monitors: the moment a filing is detected
    (and extracted-text mode or fast track is ON, and the title is not
    administrative junk) the download starts in the background
    (app/analyzer/pdf_cache.py); the analyzer reads cache-first. Saves
    0.2-1.2s per analysis.
 4. [DONE] Text extraction module (app/analyzer/pdf_extract.py),
    PyMuPDF, graceful failure -> legacy fallback.
 5. [DONE] Hindi filter (Devanagari-dominant lines dropped).
 6. [DONE] Page selection: first 2 pages + keyword/digit-scored pages,
    24k-char budget.
 7. [DONE] Scanned-PDF detection -> reason="scanned_pdf" -> fallback
    (no OCR in the hot path).
 8. [DONE] {{extracted_text}} placeholder + append_extracted_document;
    "Send extracted PDF text to AI" toggle in Settings, default OFF,
    falls back to URL mode on any extraction failure.
 9. [DONE] NO_TRADE default stance in the extracted-text footer: BUY/
    SELL requires citing a fact from the filing text. (Few-shot examples
    of routine filings can still be added to the DEFAULT prompt via the
    Prompts page.)

PHASE 2 — TWO-TRACK SIGNALS (best trades stop waiting for the LLM)
------------------------------------------------------------------
10. [DONE] Deterministic fast track (app/analyzer/fast_track.py):
    order win with explicit Rs-crore value (confidence tiers by size),
    KMP resignation (MD/CEO/CFO/WTD/chairman, succession-guarded),
    buyback with value. "Deterministic fast track" toggle in Settings,
    default OFF. PLUS the HYBRID path: order-context headline with no
    value (typical NSE phrasing) -> value parsed deterministically from
    the filing PDF text near the order mention (~1s, still no LLM);
    cancellation wording anywhere in the text kills it. KNOWN GAP:
    deal value is not scaled vs market cap — gate with rules
    (deal_value_inr_crore thresholds) until a market-cap feed lands.
11. [DEFERRED] XBRL parser for financial results: needs live NSE/BSE
    XBRL attachment URLs + taxonomy mapping — build against real
    filings during market hours, not blind.
12. [DONE] Routing in the analyzer: fast-track match -> rules engine
    directly (llm_ms=0); non-match -> LLM track. Both tracks feed the
    same rules engine, risk checks, and signals.new channel.

PHASE 3 — LLM TRACK UNDER ~8s
-----------------------------
13. [DONE] LLM_MAX_TOKENS default 1024 -> 400, editable in Settings
    ("AI max output tokens"). NOTE: the project .env pins 512, which
    stays effective until changed — a real signal JSON measured ~170
    completion tokens, so 400 has 2x+ headroom.
14. [PARTIAL] Benchmark: real pipeline measured 2026-07-04 ~22:00 IST —
    PDF fetch 200-1200ms, extract <80ms, DeepSeek (deepseek-v4-flash)
    ~2.3-2.4s, TOTAL ~2.5-2.7s end-to-end. Already under the 10s
    target off-peak; re-check during market hours via the
    analyzer.pipeline_timing logs. Groq/Gemini/Claude comparison needs
    API keys — only worth doing if market-hours DeepSeek p95 > 5s.
15. [DONE] Retries: settings-driven (LLM_MAX_RETRIES=1 default,
    LLM_RETRY_BACKOFF_SECONDS=0.5) — worst case ~0.5s of retry dead
    time instead of 7s. Explicit max_retries args still win (tests).
16. [DONE] Hard end-to-end deadline: PIPELINE_DEADLINE_SECONDS
    ("Signal deadline" in Settings, 0 = off by default). Late analyses
    are stored (Phase 4 data) but the signal is BLOCKED with reason
    pipeline_deadline. Recommended ~15s once market-hours timing is
    confirmed.
17. [DONE - EXPOSED] MAX_NEWS_AGE_SECONDS now editable in Settings
    ("Max news age"); tighten from 90s after reading a few days of
    timing logs.

PHASE 4 — DATA COLLECTION (passive; starts as soon as Phase 1 ships)
--------------------------------------------------------------------
18. [DONE] Outcome logger (app/services/outcome_logger.py +
    signal_outcomes table): for EVERY signal (approved AND blocked)
    records the Fyers price at signal time and +5m/+30m with % moves
    and a data-quality note. "Signal outcome tracking" toggle in
    Settings, default ON (pure telemetry). +1d dropped by design —
    the strategy is intraday-only. Analysis inputs (extracted text,
    track, timings) already live on analyses.raw_response; join via
    signal_id. Restart loses in-flight samples (rows keep a note).
19. [DONE 2026-07-10] Review/export view: the Outcomes page (UI) +
    GET /api/outcomes, /api/outcomes/summary, /api/outcomes/export.csv
    — table, per-event-type performance chart, CSV for offline ML.

PHASE 5 — PRE-FILTER MODEL (after ~1-2k logged announcements)
-------------------------------------------------------------
20. Weak-label materiality: "moved >X% vs index within 30 min".
21. Train a small local classifier (FinBERT/IndicBERT-family, <100ms)
    to kill routine noise before any LLM call; wire in as step 0.5
    next to the staleness gate, fail-open.

PHASE 6 — FINE-TUNING (only after 1-2 months of Phase 4 data)
-------------------------------------------------------------
22. Fine-tune for fact/event extraction, NOT buy-sell direction; the
    rules engine stays the decision-maker.
23. Backtest against logged history before it goes live.

R1. [DONE] Pipeline Latency view: GET /api/metrics/pipeline-latency —

    POST /api/metrics/health-report/send.
R3. [DONE] Performance-Weighted Sizer (app/risk/perf_sizer.py): per-

    per-trade risk %% (>60% WR & >1.5R → 1.0%; <50% WR or <1.0R → 0.5%;
    else base 0.75%). Fail-safe: <PERF_SIZER_MIN_TRADES closed trades →
    base %% unchanged. Applied before ramp/throttle/VIX clamps.
R4. [DONE] Sentiment Decay Curve: the target multiple shrinks with news
    age at order time (<2s full, <5s ×0.8, older ×0.6 — SENTIMENT_DECAY_*).
    The stop is never widened; only the reward expectation comes in.
R5. [DONE] Signal Outcomes Viewer (Phase 4 item 19 complete): GET
    /api/outcomes + /summary + /export.csv; Outcomes page in the UI
    (table, per-event-type avg-5m-move chart, event filter, CSV export).

R6. [DONE] Circuit Breaker History: every trip/kill/resume persists a
    BREAKER_* risk_events row (threshold, value at trip, action taken);
    GET /api/risk/breaker-history; panel on the Settings page.
