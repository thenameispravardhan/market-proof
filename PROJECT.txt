1. WHAT IT DOES
--------------------------------------------------------------------------------
The AI News Trading Bot is an event-driven, low-latency intraday trading system.
It continuously polls NSE and BSE corporate-announcement feeds. When a fresh
material filing appears (order win, results, resignation, buyback, M&A, …) it:

  1. Detects and de-duplicates the filing (SHA-256 content hash).
  2. Optionally pre-fetches and extracts the filing PDF text (PyMuPDF).
  3. Classifies the event — either deterministically (fast track) or via the
     DeepSeek LLM — into a structured JSON verdict (event type, sentiment,
     sentiment score, confidence, recommendation, key numbers).
  4. Evaluates the verdict against operator-defined rules (the rules engine),
     producing a BUY / SELL / HOLD / BLOCK action.
  5. Sizes and gates the trade through a strict, non-bypassable risk engine and
     portfolio circuit breakers.
  6. Executes it — simulated (paper backend) or real (Fyers) — and then manages
     the position to a stop-loss, target, trailing stop, time exit, or EOD
     square-off.
  7. Streams every step to the React dashboard over WebSockets and fans events
     out to notification channels and webhooks.

Everything is controlled from the browser UI. There are no file sentinels and no
CLI-only gates — every operational switch lives in the dashboard.

--------------------------------------------------------------------------------
2. WHY IT EXISTS (THE EDGE)
--------------------------------------------------------------------------------
Material corporate announcements move NSE/BSE stocks within seconds. Retail
traders reacting to Telegram/Twitter alerts enter the move halfway through. This
bot automates the "first read" and "first trade" to capture the initial spike,
while enforcing strict pre-trade risk controls so bad data or an LLM
hallucination cannot blow up the account.

Core belief (see memory: "Early entry is the edge"): enter fast on the news
spike; never fix whipsaw or slippage by delaying entry — fix it in the stop,
the sizing, and the slippage caps. News alpha decays in minutes, which is why
the whole system is intraday-only and time-boxed.

3. ARCHITECTURE PIPELINE & DETAILED WORKFLOW
--------------------------------------------------------------------------------
One FastAPI process. All internal messaging goes over an in-memory async event
bus (app/services/event_bus.py) — publish/subscribe channels, no external
broker. Six logical tracks (T1–T6) run as asyncio tasks under the app lifespan.

   [NSE / BSE filings]
          │  poll every POLL_INTERVAL_SECONDS
          ▼
   T2 Monitors ──publish──► "announcements.new"
          │  (dedupe by content_hash, prefetch PDF, drop Hindi/junk)
          ▼
   T3 Analyzer  (subscribes announcements.new)
          │  staleness gate → AI on/off → pre-LLM noise filter →
          │  FAST TRACK (headline) | HYBRID (headline+PDF) | LLM (DeepSeek)
          │  → schema validate → rules engine → pipeline deadline
          ▼
      "signals.new"  (BUY / SELL / HOLD / BLOCK, entry/SL/target in rationale)
          │
          ▼
   T4 Execution (subscribes signals.new)
          │  RiskEngine.evaluate (hard gates + sizing) →
          │  circuit-breaker entry check → route to backend
          ▼
   [PaperBackend]  or  [FyersLiveBackend]  ──► "trade.executed"
          │
          ▼
   TradeManager (watches QuoteFeed) → STOP / TARGET / TRAIL / TIME_EXIT /
          │                            EOD square-off → realised P&L → "trade.closed"
          ▼
   T5 Notifications + Webhooks   |   T6 Operational REST/WS surfaces (UI)
   Phase-4 OutcomeLogger records price at signal, +5m, +30m for every signal.

--- DETAILED STEP-BY-STEP (analyzer, app/analyzer/service.py) ---

 0. Idempotency: skip if an `analyses` row already exists for the announcement.
 0.5 AI master switch: if AI_ANALYSIS_ENABLED is OFF (Dashboard toggle), store a
     placeholder analysis (`ai_analysis_disabled`) and stop — no LLM, no signal.
 1. Staleness gate: if (now − filed_at) > MAX_NEWS_AGE_SECONDS, store a
     `stale_news` placeholder and stop. A startup sweep also pre-marks the whole
     backlog so a restart/replay never fires the LLM on old news.
 2. Pre-LLM noise filter (PRE_LLM_FILTER_ENABLED): drop clearly-administrative
     filings (trading-window notices, compliance certs, newspaper publications)
     before paying for an LLM call; keeps the serial queue clear for real movers.
 3. Fast track (FAST_TRACK_ENABLED): a few unambiguous headline shapes emit a
     signal in milliseconds with NO LLM. Non-matches fall through.
 4. Extracted-text / hybrid: optionally download + extract the PDF (cache-first;
     the monitor prefetched it). Hybrid parses an order value from the text.
 5. LLM track: render system+user prompts, call DeepSeek with a hard timeout,
     validate the JSON against the Pydantic schema.
 6. Rules engine: evaluate the analysis against every ENABLED strategy's enabled
     rules (priority ASC, first match wins) → action + params.
 7. Trade levels: compute entry / stop-loss / target / RR (v1 deterministic
     stub packed into the signal rationale string).
 8. Pipeline deadline (PIPELINE_DEADLINE_SECONDS, 0 = off): if the fully-analysed
     filing is now older than the deadline, store the analysis (training data)
     but BLOCK the signal (`pipeline_deadline`) — a late entry is worse than none.
 9. Persist analysis + signal; publish "signals.new"; write an audit entry.

Concurrency: up to 2 announcements are analysed in parallel (bounded semaphore
to respect DeepSeek rate limits). Prompt templates, rules, and the sector map
are cached in-process for 5 minutes and invalidated on `settings.updated`.

7. KEY CONCEPTS & TRADING PARAMETERS
--------------------------------------------------------------------------------
• Trading mode (TRADING_MODE): "paper" (simulated) or "live" (real Fyers).
  Switched via POST /api/settings/trading-mode with a literal `confirm: true`
  body; the UI adds a typed-"LIVE" confirmation. The old `.i_accept_live_risk`
  file sentinel has been REMOVED — control is frontend-only. On switch, the
  Settings cache hot-reloads and `settings.updated` fires so the execution
  manager drops cached live backends. Turning Fyers OFF blocks trades but keeps
  the price feed + OAuth alive (memory: "Fyers enabled = trade switch only").

• Intraday only, no carry-forward: every trade is MIS/intraday. TIME_EXIT and
  EOD square-off always flatten. There is deliberately no delivery/overnight
  path (memory: "Intraday only, no carry-forward").

• The speed budget: news alpha is gone in seconds/minutes.
    MAX_NEWS_AGE_SECONDS   — reject news older than this before the LLM.
    LLM_TIMEOUT_SECONDS    — discard the opportunity if DeepSeek is slow.
    PIPELINE_DEADLINE_SECONDS — hard end-to-end deadline (0 = off) → BLOCK late.
    MAX_HOLD_SECONDS       — force a TIME_EXIT after the spike-capture window.

• Two-track analyzer: deterministic fast track for a few unambiguous headline
  shapes; DeepSeek for everything else. Both feed the same rules + risk path.

• Operator-curated rules: there are NO hard-coded trading triggers. Startup no
  longer seeds default rules; the operator builds them in the Rules UI and a
  restart never resurrects deleted rules (memory: "Rules: fresh slate").

• Intraday leverage (INTRADAY_LEVERAGE, ~5x): NOTIONAL caps (sizing clamp,
  single-name cap, sector cap) are computed against buying power = equity ×
  leverage. Real-money limits (per-trade risk %, daily/weekly/monthly loss)
  stay on raw equity — leverage multiplies exposure, never the money at risk.

• Fail-safe defaults: missing market data (VIX, spread, ATR, ADV) makes the
  relevant filter SKIP (warn) or, in live mode for liquidity, BLOCK — it never
  fakes a pass. A cold live price feed blocks the trade (NO_LIVE_PRICE).

8. THE TWO-TRACK ANALYZER (FAST TRACK / HYBRID / LLM)
--------------------------------------------------------------------------------
Fast track (app/analyzer/fast_track.py, FAST_TRACK_ENABLED, default per config
ON — see §11 drift note). Tight, high-conviction patterns only:
  1. ORDER_WIN with an explicit INR value ("bags order worth Rs 450 crore").
     Confidence scales with value. INR only (Rs/₹/INR + crore/cr/lakh/lac/
     million/mn/billion/bn), converted to crore.
  2. KMP resignation — MD / CEO / CFO / whole-time director / chairman. Routine
     succession ("resignation and appointment") and independent-director exits
     are left to the LLM.
  3. BUYBACK with an explicit INR value.
Hybrid path: an order-context headline with NO value (typical NSE phrasing) →
  extract the PDF text and parse the value deterministically near the order
  mention (~1s, still no LLM); cancellation wording anywhere in the text kills
  it. Known accepted blind spot: deal value is NOT scaled vs market cap — gate
  with rules (deal_value_inr_crore thresholds) until a market-cap feed lands.

LLM track (DeepSeek). Prompt templates live in the `prompt_templates` table and
are fully operator-editable (Prompts page) with version history. A single
DEFAULT template handles all event types; the detected event type is injected as
context. Templates carry model, temperature, max_tokens, and DeepSeek-v4
inference controls: reasoning_effort (low|medium|high), thinking_enabled,
stream. The completion is capped by min(template.max_tokens, LLM_MAX_TOKENS).

Extracted-text mode (SEND_EXTRACTED_TEXT, default OFF): when ON, DeepSeek gets
the real filing text (Hindi lines dropped, first 2 pages + keyword/digit-scored
pages, ~24k-char budget) plus a NO-TRADE-by-default footer requiring a BUY/SELL
to cite a fact from the filing. Any download/extraction failure (scanned PDF,
encryption, missing wheel, timeout) falls back to the legacy metadata-only
prompt — this mode can degrade but never block a signal (memory:
"Extracted-text toggle, non-destructive").

AnalysisResponse schema (schemas.py):
  event_type ∈ {ORDER_WIN, ACQUISITION, MERGER, DIVIDEND, BUYBACK, STOCK_SPLIT,
  BONUS, RIGHTS_ISSUE, Q1_RESULTS, Q2_RESULTS, Q3_RESULTS, Q4_RESULTS,
  ANNUAL_RESULTS, BOARD_MEETING, OTHER} (+DEFAULT for templates);
  summary; sentiment ∈ {positive, neutral, negative}; sentiment_score −100..100
  (fractional 0..1 scores auto-scaled ×100); confidence 0..1;
  recommendation ∈ {BUY, SELL, HOLD}; reasoning; key_numbers{deal_value_inr_crore,
  stake_change_pct, dividend_per_share, buyback_value_inr_crore}. Invalid/novel
  categories are coerced to OTHER rather than discarding the analysis.

9. THE RULES ENGINE (app/analyzer/rules_engine.py)
--------------------------------------------------------------------------------
Pure function over loaded rules and the analysis dict. Live evaluation runs every
ENABLED strategy's enabled rules together, ordered by (priority ASC, id ASC),
first match wins; no match → HOLD fallback (persisted for observability but
marked blocked so nothing trades).

Conditions JSON supports `all_of` (AND) and `any_of` (OR) groups of
{field, op, value}. A rule matches when all_of is fully satisfied AND any_of has
≥1 satisfied entry (missing/empty group = satisfied).

Operators: ==, !=, in, not_in, >=, <=, >, <, between ([low, high] inclusive).
  == / != are case-insensitive for strings; numeric ops on a missing value are
  a non-match (fail-safe); malformed rules are skipped with a log warning.

Fields:
  Analysis:  event_type, sentiment, sentiment_score, confidence, recommendation,
             deal_value_inr_crore, stake_change_pct, dividend_per_share,
             buyback_value_inr_crore.
  Market:    sector (enriched live from the sector map), price, change_pct,
             adv_crore (enriched only when a live quote is supplied),
             atr_pct, india_vix, spread_pct (schema-ready; populate in Phase 5).

The UI rule builder is limited to 4 typed conditions (memory: "Rules: fresh
slate & cross-strategy eval"); the engine itself is more general. Rules can be
dry-run against a sample analysis via GET/POST /api/rules/dry-run.

10. THE RISK ENGINE (app/risk/engine.py)
--------------------------------------------------------------------------------
RiskEngine.evaluate(signal, …) → RiskDecision{approved, violations[], sizing,
context}. Every signal routes through it; there is no override flag, no
force=True, no "if is_test" branch — the only way a rule fails to apply is by
bypassing the manager, and the manager routes every signal through the engine.

Position sizing:
    qty = floor( (equity × risk_pct/100) / |entry − stop_loss| )
  then clamped to the notional single-name cap (the SMALLER of risk-based and
  notional-based qty wins). risk_pct = strategy/settings ceiling, reduced by the
  graduated new-account ramp and any RiskState throttle and a (fail-safe) VIX
  multiplier. Notional caps use buying power = equity × INTRADAY_LEVERAGE; equity
  is a real ledger (capital + realised + unrealised), anchored in LIVE mode to
  the real Fyers balance when a funds feed is attached (else PORTFOLIO_VALUE).

Hard gates (each blocks the signal):
  R1  action must be BUY/SELL (HOLD/BLOCK → blocked)
  R2  confidence > 0
  R2b confidence ≥ MIN_SENTIMENT_CONFIDENCE floor (manual orders carry 1.0)
  R0  stop_loss present and > 0 (no SL → cannot size safely → block)
  R10 symbol not on the strategy's blocklist
  R11 shorting: a SELL that OPENS a short requires SHORTING_ENABLED (closing a
      long is always allowed)
  RISK_NO_ENTRY_PRICE  entry from quote if not supplied; none → block
  R3  qty ≥ 1 (rounds to 0 → block)
  R4  trade risk ≤ MAX_CAPITAL_RISK_PCT of equity
  R5  daily realised loss < DAILY_MAX_LOSS_PCT of equity
  R6  open positions < MAX_CONCURRENT_POSITIONS (adding to a held name is exempt)
  R7  (existing + new) single-name value ≤ MAX_SINGLE_POSITION_PCT of buying power
  R8  min liquidity: block if known ADV < MIN_LIQUIDITY_CRORE; unknown ADV →
      block in LIVE only when REQUIRE_KNOWN_LIQUIDITY, else warn+allow
  R12 bid/ask spread ≤ MAX_SPREAD_PCT (fail-safe skip until an L1 feed exists)
  R9  sector exposure ≤ SECTOR_CONCENTRATION_PCT of buying power
  R13 distinct names in a sector ≤ MAX_POSITIONS_PER_SECTOR, AND the
      one-name-per-event window: block a 2nd same-sector entry within
      SECTOR_CLUSTER_WINDOW_SECONDS of the first (correlated news cluster)

Volatility-aware stops (ATR_ENABLED): when ATR is available the initial stop is
ATR×ATR_STOP_MULT clamped to [DEFAULT_SL_MIN_PCT, ATR_MAX_STOP_PCT] of entry;
otherwise the percentage stop applies. ATR comes from Fyers history candles and
is fail-safe (no account → % stop). (memory: "Risk edge enhancements").

Static sector map: ~60 large-caps across IT, BANK, NBFC, ENERGY, FMCG, AUTO,
PHARMA, METALS, INFRA, TELECOM, CEMENT, POWER, REALTY, CONSUMER_DURABLES.
Unknown symbol → sector rules simply don't apply (allow).

11. CIRCUIT BREAKERS & KILL SWITCH (app/risk/circuit_breakers.py)
--------------------------------------------------------------------------------
A persistent, account-wide safety layer ABOVE the per-trade engine, backed by the
singleton `risk_state` row (survives restarts). A background monitor in the
lifespan calls evaluate_breakers() every ~10s; entry_allowed() is checked before
every new entry.

Breakers (thresholds from Settings; anchors reset on the IST calendar):
  daily loss ≥ DAILY_MAX_LOSS_PCT              → halt + flatten (clears next day)
  monthly drawdown ≥ MONTHLY_MAX_DRAWDOWN_PCT  → halt + flatten + force paper
                                                 (clears next month)
  weekly loss ≥ WEEKLY_MAX_LOSS_PCT            → throttle risk % (WEEKLY_BREACH_RISK_PCT)
  consecutive losers ≥ MAX_CONSECUTIVE_LOSERS  → cooldown pause
                                                 (CONSECUTIVE_LOSER_PAUSE_MINUTES;
                                                  a high-conviction signal ≥
                                                  CONSECUTIVE_LOSER_RESUME_CONFIDENCE
                                                  can resume early)
  trades today ≥ MAX_TRADES_PER_DAY            → no new entries
A manual kill (POST /api/risk/kill) only clears via POST /api/risk/resume.
On a flatten, TradeManager.close_all(reason="CIRCUIT_BREAKER") squares off.

--------------------------------------------------------------------------------
12. EXECUTION, TRADE MANAGEMENT & MARKET DATA
--------------------------------------------------------------------------------
Execution manager (app/execution/manager.py): subscribes signals.new; loads the
signal + its strategy + the strategy's broker account (the routing key); picks a
backend (paper when account.paper_mode OR TRADING_MODE=='paper', else Fyers
live); parses entry/SL/target from the signal rationale (falls back to the last
cached quote); runs the risk engine; on block writes a risk_events row, marks the
signal blocked, persists a blocked trade, publishes risk.blocked (no order); on
approve calls backend.place_order and persists a trade with the broker status.
One backend is cached per broker account; a Fyers OAuth token rotation
re-injects the new token; `settings.updated` drops mode-coupled backends.

Order execution safeguards (RISK.md §5): auto entries use an IOC marketable-limit
(last ± ENTRY_BUFFER_PCT) cancelled after ORDER_FILL_TIMEOUT_SECONDS; a fill worse
than MAX_SLIPPAGE_PCT off the intended entry is rejected; an anti-chase guard
blocks entries that have already run past MAX_ENTRY_DRIFT_PCT in the trade's
favour (ENTRY_DRIFT).

Trade manager (app/execution/trade_manager.py): registers each filled entry as a
ManagedPosition and watches the QuoteFeed. Every QUOTE_REFRESH_SECONDS it exits
on: TIME_EXIT (now − opened_at ≥ max_hold_seconds); long STOP (last ≤ SL) /
TARGET (last ≥ target); short STOP (last ≥ SL) / TARGET (last ≤ target). An
explicit target fires a FULL exit; scale-out / trailing (SCALE_OUT_R,
TRAIL_ACTIVATE_R, TRAIL_DISTANCE_R) run only when no explicit target is set
(memory: "Explicit levels win over scale-out"). Managed levels persist on the
`positions` row so exits re-arm after a restart. Backs the dashboard's manual
close / square-off-all. Entry and exit share ONE price source; a cold live feed
blocks rather than filling at a synthetic price (memory: "No synthetic entry
fill").

Market data (app/execution/): MarketDataBus holds last quotes and a quote sink
that bridges every tick onto the /ws "quotes" channel (sub-second UI pushes).
QuoteFeed is WS-first (Fyers data socket) with a one-shot REST fallback; the
FyersStreamManager keeps the index symbols always-subscribed for the status-bar
ticker. Market-data lookups key on the Fyers token, not the `enabled` flag, so
disabling trading keeps prices flowing.

--------------------------------------------------------------------------------
13. MONITORS (app/monitors/)
--------------------------------------------------------------------------------
NSEMonitor and BSEMonitor each run an independent poll loop at the live
POLL_INTERVAL_SECONDS (picked up per-tick, so a UI change takes effect on the
next poll). They fetch the exchange announcement feed via httpx, with a warm
shared Playwright browser (browser_pool.py) as a fallback when the CDN blocks the
fast path. Each new filing is de-duplicated by content_hash =
SHA-256(exchange|symbol|filed_at|pdf_url), its PDF is prefetched in the
background (when fast-track / extracted-text is on and the title isn't
administrative junk), and an "announcements.new" event is published. Polling too
aggressively risks NSE/BSE 403/429 rate-limits — raise the interval if the logs
show `monitor.retry` spam.

--------------------------------------------------------------------------------
14. NOTIFICATIONS & WEBHOOKS
--------------------------------------------------------------------------------
Notifications (app/notifications/): a manager subscribes to the event bus and
fans events out to operator-configured channels. Channel kinds: telegram,
discord, email, webhook. Each channel has a JSON config and an events filter
(csv, e.g. signal,trade,risk_halt,error). Every send is recorded in
`notification_log` (sent | failed | skipped).

Webhooks (app/webhooks/): the outbound dispatcher POSTs bus events to registered
webhook URLs (HMAC-SHA256 signed with the webhook's secret), recording each
attempt in `webhook_deliveries`. Inbound webhooks are accepted at
POST /api/webhooks/in/{id} (bearer-verified). Fyers order postbacks arrive at
POST /api/fyers/postback (HMAC-verified with FYERS_POSTBACK_SECRET);
scripts/register_fyers_webhook.py registers the row and copies the secret. Local
inbound delivery typically needs a public tunnel (e.g. cloudflared).

--------------------------------------------------------------------------------
15. BACKTESTING (app/backtest/)
--------------------------------------------------------------------------------
Replays historical announcements through the SAME analyzer→rules→risk→paper
pipeline. Critically, each run builds a throwaway in-memory SQLite SANDBOX seeded
with copies of the strategy, its rules, and the broker account, so simulated
analyses/signals/trades/positions never pollute the live Dashboard, Trade
History, or the live risk engine's concurrency/sector counts. The live DB is
touched only to read source announcements + config and to write the final
`backtest_runs.results` blob, which the Backtest page renders. Prices come from a
pluggable PriceModel (synthetic-return default; a real Fyers historical loader
can be swapped in). Single-threaded, chronological; metrics via metrics.summarise
(equity curve, win rate, R-multiples, drawdown).

24. TROUBLESHOOTING
--------------------------------------------------------------------------------
- Blank UI / dashboard missing: frontend/dist wasn't built. run.ps1 builds it;
  in dev mode use the Vite server on :5173/:5174.
- Fyers login error -50: your public IP isn't whitelisted in the Fyers API
  dashboard — update it.
- Orders reject as the wrong app: Fyers app-id/token mismatch — see the memory
  note and scripts/fix_fyers_app_id.py; follow activate→disconnect→reconnect.
- LLM timeouts: DeepSeek congested — check LLM_TIMEOUT_SECONDS and the
  analyzer.pipeline_timing logs; the analyzer retries once then discards.
- No trades in live mode: confirm TRADING_MODE=live, a live Fyers account is
  connected + enabled, the market is open (or ENFORCE_MARKET_HOURS is off for
  testing), and no circuit breaker / risk gate is blocking (VIX, spread,
  concurrency, sector, daily loss). Check /api/risk/state.
- "NO_LIVE_PRICE" / blocked entries: the live feed is cold — by design the system
  blocks rather than filling at a synthetic price.
- Backend wedged after an edit: uvicorn --reload can hang on open /ws — probe
  :8000 and restart detached.

25. DESIGN PHILOSOPHY & INVARIANTS
--------------------------------------------------------------------------------
• No black boxes: the operator curates the logic (prompts + rules); the bot
  provides the framework and the guardrails.
• Latency is the product: fail fast; a late entry is worse than no entry.
• Early entry is the edge: never fix whipsaw by delaying entry — fix the stop,
  the sizing, and the slippage caps.
• Intraday only: no delivery, no overnight carry; TIME_EXIT + EOD square-off
  always flatten.
• Fyers-only pricing: no public-feed fallback; a cold feed blocks, never fills
  at a synthetic price; entry and exit share one price source.
• Fail-safe defaults: missing data → skip/no-trade (or block in live for
  liquidity), never a faked pass.
• Non-bypassable risk: every signal goes through the risk engine + circuit
  breakers; no override flag exists.
• Frontend-only control: every operational switch lives in the UI; no file
  sentinels, no CLI gates. Going live needs a typed "LIVE" confirmation.
• Non-destructive evolution: new pipeline features ship behind toggles that
  default to the existing behavior; saved prompt edits and deleted rules survive
  restarts (no silent re-seeding).
