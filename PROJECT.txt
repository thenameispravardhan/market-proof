1. WHAT IT DOES
--------------------------------------------------------------------------------
The AI News Trading Bot is an ultra-low-latency event-driven trading system. It 
monitors corporate announcement feeds from the NSE and BSE in real-time. Upon 
detecting a material filing (e.g., earnings, order wins, M&A), it downloads the 
PDF, extracts text, and uses a Large Language Model (DeepSeek) to classify the 
event. The extracted data is run through an operator-defined rules engine and 
strict risk gates. If conditions are met, it places an entry/exit trade via the 
Fyers API—all within a tight 20-second budget.

--------------------------------------------------------------------------------
2. WHY IT EXISTS (THE EDGE)
--------------------------------------------------------------------------------
Material corporate announcements (order wins, resignations, buybacks, results) 
move NSE/BSE stocks in seconds. Retail traders relying on Telegram or Twitter 
alerts usually enter the move halfway through. This bot automates the "first 
read" and "first trade" sequence to capture the initial momentum. It removes 
human latency while enforcing strict pre-trade risk controls so the operator 
cannot blow up the account on bad data or hallucinations.

--------------------------------------------------------------------------------
3. ARCHITECTURE PIPELINE
--------------------------------------------------------------------------------
The system operates asynchronously via a central, in-memory event bus. It is 
split into six specialized tracks (T1-T6):

   [NSE/BSE Filings] 
          │
          ▼
     T2: Monitors    ───► [New Announcement Event]
          │
          ▼
     T3: Analyzer    ───► (Fast Track OR DeepSeek LLM) ──► [Rules Engine]
          │                                                       │
          ▼                                                       ▼
     T4: Execution   ◄──────────────────────────────────── [Trade Signal]
          │
          ▼
   [Fyers API (Live)] OR [Paper Trader (Sim)] ───► T5: Notifications / Webhooks

--------------------------------------------------------------------------------
4. CORE TRACKS (T1 - T6)
--------------------------------------------------------------------------------
T1 — Infrastructure (app/main.py, app/api/*, app/db/*, app/services/*)
  The backbone. FastAPI application, lifespan-managed startup/shutdown, SQLite 
  database via SQLAlchemy, WebSocket event bus for real-time internal messages, 
  global Pydantic Settings, structured JSON logging, and the frontend SPA host.

T2 — Monitors (app/monitors/{nse,bse,base,manager}.py)
  Scrapers polling NSE & BSE endpoints every POLL_INTERVAL_SECONDS (default 2s).
  Uses `httpx` for fast polling with a `playwright` headless browser fallback.
  It dedupes filings, pre-fetches PDFs, detects language, and publishes 
  `announcements.new` to the bus.

T3 — Analyzer (app/analyzer/*)
  Subscribes to new announcements and determines tradability via two tracks:
  • Fast Track (Deterministic): Order wins with explicit Rs-crore values, KMP 
    resignations, or buybacks. Bypasses the LLM (llm_ms=0) and goes straight 
    to the rules engine.
  • LLM Track (DeepSeek): Sends the filing text and prompt to DeepSeek. Parses 
    the JSON response (via Pydantic) to classify sentiment and facts, then feeds 
    the rules engine.

T4 — Execution (app/execution/*)
  Routes signals through the Risk Manager. Checks position sizing, capital caps, 
  and daily loss limits. 
  • Paper Mode: Synthetic fills with realistic slippage and latency.
  • Live Mode: Real orders via Fyers REST and WebSockets for fill updates.
  Handles trade lifecycle: Stops, Targets, Scale-outs, Trailing Stops.

T5 — Notifications & Webhooks (app/notifications/*, app/webhooks/*)
  Fans out events to Telegram, Discord, Email, and generic webhooks. Also 
  manages inbound Fyers postbacks (requires a cloudflared tunnel locally).

T6 — Operational Surfaces (app/api/*)
  The control plane. REST APIs for health, audit logs, dynamic settings, LLM 
  prompts, rules, broker management, backtesting, and market data. Consumed by 
  the React-based UI.

7. KEY CONCEPTS & TRADING PARAMETERS
--------------------------------------------------------------------------------
• Trading Mode (TRADING_MODE):
  "paper" for simulated execution. "live" for real Fyers execution. Live mode 
  requires a connected account AND a hidden `.i_accept_live_risk` file.

• The 20-Second Budget:
  The absolute maximum time allowed from news filing to Fyers order.
  - MAX_NEWS_AGE_SECONDS = 90 (Ignore stale news)
  - LLM_TIMEOUT_SECONDS = 18
  - MAX_HOLD_SECONDS = 1080 (Force square-off after 18 minutes)

• Two-Track Analyzer:
  Speed vs. Comprehension. Deterministic fast-track matches keywords + numbers 
  (e.g., "Rs 500 cr order"). Complex unstructured filings go to DeepSeek. Both 
  are evaluated by the same rule engine.

• Operator-Curated Rules:
  There are NO hard-coded trading triggers. You must use the UI to build rules 
  combining events, sentiment thresholds, and modifiers (AND/OR/NOT).

• Dynamic Risk Framework (RISK.md):
  - Pre-trade: Minimum sentiment confidence (0.7), India VIX caps.
  - Position sizing: Scales relative to MAX_CAPITAL_RISK_PCT. Uses 
    INTRADAY_LEVERAGE (e.g., 5x) for notional caps.
  - Portfolio limits: DAILY_MAX_LOSS_PCT and weekly drawdowns enforce hard stops.
  - Clustering blocks: Prevent over-concentration in one sector (SECTOR_CONCENTRATION_PCT).

8. THE REST API (ROUTER MAP)
--------------------------------------------------------------------------------
Base Path: /api/*
• /health               : App status
• /settings/*           : Global overrides (saved to DB)
• /trading-mode         : Switch Paper ↔ Live
• /broker-accounts/*    : Fyers credentials & connection status
• /prompts/*            : System prompt templates for the LLM
• /rules/*              : Trade logic conditions (+ /dry-run)
• /strategies/*         : Risk bundles
• /market/*             : Quotes, historical data, indices
• /orders/*             : Place/Cancel manual or auto orders
• /positions/*          : View/Square-off holdings
• /risk/*               : Current risk snapshots
• /notifications/*      : Alert channels
• /webhooks/*           : Fyers postbacks & outbound alerts
• /analyses/*           : Re-run LLM on past filings
• /ws                   : Global WebSocket (signals, quotes, positions)

12. SETUP & EXECUTION GUIDE
--------------------------------------------------------------------------------
Prerequisites:
  - Python 3.11, Node.js 20+

First Boot (Local Paper Mode):
  1. cd "C:\Projects\AI News Trading Bot"
  2. python -m venv .venv
  3. .\.venv\Scripts\pip install -r requirements.txt
  4. copy .env.example .env (Edit DEEPSEEK_API_KEY inside)
  5. .\scripts\run.ps1
  6. Open http://127.0.0.1:8000/

Developer Mode:
  - Term 1: .\scripts\dev.ps1 (Runs Uvicorn with auto-reload)
  - Term 2: cd frontend && npm install && npm run dev (Runs Vite HMR)

Going Live (Fyers):
  1. Set up Fyers API App via https://myapi.fyers.in/dashboard/
  2. Populate FYERS_APP_ID, FYERS_SECRET_KEY, FYERS_REDIRECT_URI in `.env`.
  3. Run `python scripts/setup_fyers.py` to authenticate.
  4. Run `python scripts/register_fyers_webhook.py` (ensure you have a webhook 
     tunnel, e.g., Cloudflare, running if developing locally).
  5. Add a live account via the Frontend UI.
  6. Create `.i_accept_live_risk` in the root dir.
  7. Switch TRADING_MODE to live via `.env` or UI.

13. TROUBLESHOOTING
--------------------------------------------------------------------------------
- UI won't load / Blank screen: Check if Vite built the frontend successfully 
  during `run.ps1`. In dev mode, ensure Vite is running on port 5173/5174.
- Fyers Login Error -50: Your public IP is not whitelisted in the Fyers API 
  dashboard. Update your IP.
- LLM Timeouts: DeepSeek API might be congested. Check the `LLM_TIMEOUT_SECONDS`
  setting. Consider switching to a faster model via `DEEPSEEK_MODEL` if supported.
- Trades not executing in Live Mode: Ensure `.i_accept_live_risk` exists, the 
  market is open (or you bypassed time checks for testing), and the Risk Engine 
  isn't blocking due to high VIX or missing Capital limits.

--------------------------------------------------------------------------------
14. DESIGN PHILOSOPHY
--------------------------------------------------------------------------------
• No Black Boxes: Operator curates the logic. The bot provides the framework.
• Latency is the Product: Every ms matters. Fail fast. If the LLM takes too 
  long, the trade is dead.
• Fail-Safe Defaults: Missing data (e.g., VIX feed down) results in a NO-TRADE.
• UI Control: All major toggles belong in the React dashboard, not just `.env`.
